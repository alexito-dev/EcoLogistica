# 10. Evaluación del stack tecnológico

[← Volver al README Principal](../../README.md)

| Criterio | MERN | FastAPI + React + PostgreSQL | Spring Boot + Angular + PostgreSQL |
|---|---|---|---|
| Curva de aprendizaje | Baja | Media | Alta |
| Costo de infraestructura | Moderado | Bajo | Alto |
| Datos geoespaciales | MongoDB geospatial | PostGIS maduro | PostGIS maduro |
| Rendimiento del PMV | Alto | Alto y asíncrono | Alto, mayor consumo inicial |
| Eco-diseño | Medio | Alto por consumo acotado | Medio-bajo por JVM |
| Soporte comunitario | Muy alto | Alto | Muy alto |

## Decisión

Se selecciona **FastAPI + React/Vite + PostgreSQL/PostGIS**, con Redis solo si una medición justifica la caché. FastAPI reduce la sobrecarga para el motor de optimización Python, PostgreSQL/PostGIS conserva consistencia y consultas geográficas, y React permite una interfaz accesible y ligera. La decisión se alinea con el perfil del equipo, el objetivo de bajo consumo cloud y la necesidad de parametrizar datos territoriales.

## Criterios de salida

El stack se revisará tras el benchmark RNF-001 y la prueba de despliegue RNF-008; cambiarlo requiere registro de decisión y actualización de versión.
