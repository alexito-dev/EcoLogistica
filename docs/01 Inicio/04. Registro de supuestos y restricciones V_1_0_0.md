# 04. Registro de Supuestos y Restricciones

**Proyecto:** EcoLogística – Optimizador de Rutas Sostenibles para DistriRápido S.A.C.  
**Curso:** Taller de Proyectos 2 – Escuela Profesional de Ingeniería de Sistemas e Informática  
**Versión:** 1.0.0  
**Fecha:** 2026-08-28  
**Estado:** Aprobado  

---

## 1. Registro de Supuestos

| ID | Categoría | Descripción del Supuesto | Impacto si es falso |
| :--- | :--- | :--- | :--- |
| **SUP-01** | Técnico | Disponibilidad de servicios de georreferenciación y mapas sin costo excesivo o dentro de capas gratuitas (OpenStreetMap/OSRM). | Alto: Requeriría cambiar el proveedor cartográfico o mockear matrices de distancia. |
| **SUP-02** | Negocio | DistriRápido S.A.C. proporcionará muestras de datos reales o representativos (pedidos, coordenadas, capacidades vehiculares y ventanas horarias). | Medio: Se deberán generar datasets sintéticos basados en zonas urbanas reales. |
| **SUP-03** | Algorítmico | Las metaheurísticas (Algoritmos Genéticos, Búsqueda Tabú o Simulated Annealing) convergerán a soluciones cercanas al óptimo en tiempos computacionales viables. | Alto: Se requerirá ajustar hiperparámetros o formular heurísticas constructivas más agresivas. |
| **SUP-04** | Organizacional | Los miembros del equipo mantendrán una dedicación constante y alineada al flujo Git Flow durante las 12 semanas del semestre. | Alto: Desfase en el cronograma de entregas e integración de ramas. |

## 2. Registro de Restricciones

| ID | Categoría | Descripción de la Restricción | Estrategia de Mitigación |
| :--- | :--- | :--- | :--- |
| **RES-01** | Tiempo | Límite improrrogable de 12 semanas académicas para la entrega del PMV operativo (Semana 1 a Semana 12). | Planificación estricta por sprints e integración continua quincenal. |
| **RES-02** | Presupuesto | Presupuesto monetario cero ($0.00 USD) para licencias comerciales; uso exclusivo de tecnologías open-source y tiers gratuitos. | Empleo de PostgreSQL, Node.js/Python, React/Vite y Leaflet/OpenStreetMap. |
| **RES-03** | Alcance | El sistema es un Producto Mínimo Viable enfocado en la web; no incluye apps móviles nativas ni hardware GPS embebido. | Interfaz web responsiva accesible desde navegadores móviles de conductores. |
| **RES-04** | Calidad y Procesos | Obligatoriedad de utilizar Git Flow, Conventional Commits, Pull Requests con revisión y Semantic Versioning sin commits directos a `main`. | Configuración de plantillas y directrices en el repositorio. |
| **RES-05** | Modelo Matemático | El algoritmo debe resolver el problema VRPTW con función objetivo multiobjetivo (distancia, tiempo, emisiones de $CO_2$). | Modelación matemática rigurosa y pruebas unitarias con benchmarks de prueba. |
