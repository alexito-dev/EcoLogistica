## 1. Marco de elicitación

Se combinarán entrevistas semiestructuradas con despachadores, observación contextual de la operación, revisión de pedidos sintéticos y talleres de validación con conductores. Se incluirán las restricciones glocales de Huancayo, conectividad 2G/3G, direcciones por referencia, accesibilidad y seguridad de datos. La participación se registrará por rol, sin publicar datos personales reales; toda necesidad se valida con el Product Owner y se convierte en requisito verificable.

## 2. Catálogo atómico

| ID | Requisito | Prioridad |
|---|---|---|
| RF-001 | El sistema debe crear un pedido cuando el operador ingrese cliente, dirección, carga y ventana horaria válidos. | Alta |
| RF-002 | El sistema debe validar y guardar la coordenada del pedido cuando la geocodificación alcance el umbral configurado. | Alta |
| RF-003 | El sistema debe permitir corregir manualmente la ubicación cuando la geocodificación sea insuficiente. | Alta |
| RF-004 | El sistema debe importar pedidos mediante una plantilla validada y reportar cada fila rechazada. | Media |
| RF-005 | El sistema debe registrar vehículos con capacidad, combustible, autonomía y turno. | Alta |
| RF-006 | El sistema debe asociar conductores disponibles a vehículos y turnos. | Alta |
| RF-007 | El sistema debe parametrizar restricciones de placa, vía y horario aplicables a la operación. | Media |
| RF-008 | El sistema debe generar una solución de rutas considerando capacidad, ventanas, distancia y emisiones. | Alta |
| RF-009 | El sistema debe mostrar distancia, duración, puntualidad estimada y CO₂ por ruta generada. | Alta |
| RF-010 | El sistema debe identificar pedidos no asignados y explicar la restricción que impidió asignarlos. | Alta |
| RF-011 | El sistema debe mostrar en un mapa la secuencia, vehículo y estado de cada entrega publicada. | Alta |
| RF-012 | El sistema debe registrar estados Pendiente, En ruta, Entregado, Incidencia y Cancelado. | Alta |
| RF-013 | El sistema debe recalcular una ruta cuando el operador registre un pedido urgente o una incidencia. | Media |
| RF-014 | El sistema debe calcular indicadores de distancia, costo, puntualidad y CO₂ para un periodo seleccionado. | Media |
| RF-015 | El sistema debe comparar una ruta optimizada contra la línea base manual registrada. | Media |
| RF-016 | El sistema debe registrar auditoría de accesos, cambios de configuración y exportaciones. | Alta |

## 3. Criterios BDD representativos

```gherkin
Escenario: Crear pedido válido
Dado un operador autenticado con permiso de pedidos
Cuando ingresa datos válidos y guarda el formulario
Entonces el sistema crea el pedido en estado Pendiente

Escenario: Generar rutas factibles
Dado un conjunto de pedidos geocodificados y una flota disponible
Cuando el operador solicita optimización
Entonces el sistema devuelve rutas con asignación, secuencia, ventanas y métricas ambientales
```
